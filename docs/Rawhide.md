# Rawhide — What's New (Nightlies)

These notes are the in-app "Update Available" text for Rawhide builds. The
nightly takes every bullet under **Unreleased** as that build's release
body, and `tools/rotate-rawhide-notes.sh <tag>` then removes the bullets it
shipped, so a note is read here once and lives on in the GitHub release.
Write one bullet per change, on one line, with a bold title. Nothing else
goes in this file; `test/hygiene/rawhide_notes_test.dart` checks that.

Last shipped nightly: `nightly-rawhide.20261020.601968c`

## Unreleased

- 🌦️ **The story's weather tints the chat** — Settings → Appearance has an Ambient scene choice (Off, or Tint only; off until you turn it on). With Tint only, a chat in a world with climate on gets a soft wash over its background that follows the story: pink at dawn, amber at evening, deep blue at night, greyer under cloud, darker in rain and storm, pale and hazy in fog, cooler when it is cold and warmer when it is hot. It paints behind the bubbles, never over them, so nothing gets harder to read, and a light theme gets a lighter touch. The stage stops working while the window is hidden or unfocused. Rain, snow and clouds come next. On the desktop and the web app.
- 🔍 **Zoom into a new character's portrait** — the portrait the character creators generate is shown bigger once it is saved as the card image, and clicking it opens it full size, where you can scroll or pinch to zoom in and pan around; click again to close. In the AI Character Creator's last step and the manual creator's Portrait step, on the desktop (the web app's creator has no portrait step).
- ⚡ **Flash attention for Gemma 4 on Vulkan is your call** — it used to be locked off, because in testing KoboldCpp crashed with it on. It still starts off, but Settings → Advanced Launch Options now has a Flash Attention for Gemma 4 switch on Vulkan machines, and the preset editor's flash attention box can be ticked for those models; both show a warning that in testing this has caused KoboldCpp to crash. With it on, the smaller chat memory sizes work for Gemma 4 too. Desktop only, like the rest of the launch options.
- 📄 **Read a model's card before you download it** — every result in the model downloader has a Model card button that opens the repo's description from HuggingFace: what the model is for, its prompt format, its licence, when it was last updated, and the model it was made from, with a button straight through to that original's card (a quant repo's own card is often just a file list). Pictures show as links instead of loading from other sites, and a gated repo says how to get access. On the desktop and the web app.
- 🔑 **HuggingFace token for gated models** — Settings → Backend has an optional HuggingFace token: with one, gated repos (official Llama and Gemma, some tunes) list their files and download in the model downloader. The token is only ever sent to HuggingFace itself, never shown again once saved, and setting it from the web app asks for your web login password like the other keys. On the desktop and the web app.
- 🧩 **The model downloader sees every file** — big quants that HuggingFace repos keep in a folder per quant (the Q5 to Q8 and F16 versions of a 70B model, say) were missing from the list; they now show up, and a quant split into parts is one row ("Q8_0 · 2 parts", with its full size and VRAM fit) and one download that fetches every part. The quant that fits your graphics card best at your context size is marked Best fit, a vision model's projector is listed as a Vision add-on and is paired with the model you download from the same repo, an upload still missing parts says so instead of offering a broken download, and a gated repo tells you to accept its licence and add a token instead of showing "No GGUF files". My Models lists a split model once at its full size and no longer shows projectors as models. On the desktop and the web app.
- 🚀 **Faster model downloads** — a big model now downloads over up to eight connections at once, each fetching its own slice of the file, instead of one connection that HuggingFace's servers cap well below a fast line; and the download no longer redraws the Model Manager for every few kilobytes that arrive, which was holding speed down on its own. Pause and resume keep every slice's progress, a slice whose connection drops picks up where it stopped, and small files or servers that cannot send slices still use a single connection. On the desktop and the web app.
- ⏯️ **Model downloads pause, resume and check themselves** — pausing a model download used to leave a cut-off file marked Completed, and Resume showed "downloading" without fetching anything; now Pause keeps the partial file, Resume carries on from where it stopped, and Cancel leaves nothing behind. A file with a published checksum is checked before it is saved (in the background, with a percentage, so the window stays responsive), a connection that goes quiet for a minute is retried instead of hanging, a download that will not fit on the drive stops at once and says how much room it needs, a server that refuses to resume makes it start over instead of hanging, and several downloads really run at the same time. On the desktop and the web app.
- 🎚️ **Model search filters and an honest fit** — the model downloader's search has a sort (most downloaded, most liked, recently updated, trending), a Roleplay only switch and a size filter (up to 13B, 14B to 34B, 35B and up); changing one searches again. The "fits your VRAM" line now uses the context size you actually chat at instead of always 16K, a machine whose graphics memory could not be read says "fit unknown" instead of pretending it has 4 GB, and typing a new search while one is still running can no longer be overwritten by the older answer. On the desktop and the web app.
- 🔍 **Model search finds roleplay tunes** — searching the model downloader for a community tune (Dark Scarlett, For-Her-Darkside, Dominatrix and the like) used to come back empty, because the search only accepted repos labelled as text generation and most GGUF quant repos carry no label at all. It now takes any GGUF repo, leaves out image, video and speech models, sorts by downloads, lists roleplay-tagged tunes first with a Roleplay badge, and loads each result's files a few at a time instead of one by one, so results arrive sooner. On the desktop and the web app.
- 🎭 **World from Character** — the Worlds page has a From Character button beside From Wiki: pick a character and, if you like, one of your 1:1 chats with them, and the same wizard builds a world from it. The chat is skimmed into an index first (one pass per 50 messages, with that stretch's Journal cards and Growth rings, and the chat's Objectives in the closing notes), the card's own sections go straight onto the index, and the scout, shelf, write and Review steps are the ones World from Wiki has. Three modes say how far the writer may go: Facts only adds no fact (a card nothing supports is dropped, weather only if the chat shows some), Faithful keeps every fact as the spine and may round it out but never adds a named thing or an event, Creative may invent around the facts; whatever a mode added is marked on the Review step so you can drop it before Mint. The chat picker warns when a chat is short (under 100 messages) or too short to skim (under 40) and advises against Full under 200; it warns, never blocks. The character and you never get a card, the persona is written as a macro so an exported world carries no name, and the minted world wears a "from <character>" tag. On the desktop and the web app.
- ✨ **World from Wiki wears the porch** — the wizard got its uplift: a step strip in the title bar, the Book step as four cards with a job each (the world, with Where the story stands as its own story card; the saved wikis as tiles that say what each is; Quick, Full and Deep as tiles with a card count and the time to expect; the context as pills; Lorebooks and Climate as switches), the Shelf with counts, kind filters, the reviewer's word in a banner and the places as groups with Sign all here, and the progress card with its stage strip, a timer for the step it is waiting on, and Stop. Every colour comes from your theme. And the shelf no longer needs signing by hand: every card the scout proposed starts signed, so Next reads "Write 60 cards" the moment the shelf lands; untick what you don't want, or press Only the backbone for a shorter write, and fix the rest on the Review step. On the desktop and the web app.
- 🖋️ **World from Wiki: you review before you mint** — the Preview step is now a Review step, the last stop before Mint World. It shows what the reviewers did this run, then every entry grouped by place with the reviewer's verdict on it (passed first try, rewritten once and why, still marked), its text and keys editable in place, Rewrite with a note that sends that one card back around the reviewers with your note as the finding, Drop, and Keep (a pinned card is never touched again). A direction box takes your own words for the whole world — "the Royal Guard card should name all four; Karakura needs the Kurosaki Clinic" — sorts them against the shelf, rewrites the cards they name, writes the cards they ask for and drops the ones they say to drop, with a scope switch to apply the note to every card instead. Each place has "+ Add a card here". Nothing is saved until Mint World. On the desktop and the web app.
- 🔎 **World from Wiki says what it is doing** — the spinner that only said "Scouting 464 titles…" is now a progress panel on the Book and Write steps: the line for what the wizard is doing right now (rummaging through the wiki, picking the pages that matter, a reviewer reading the shelf, a revise with the finding it answers, hunting for what the shelf forgot, reading up on the pages, writing cards, walking around a place, checking the weather), the time the run has taken, and the lines before it. A hung call, a server stumble and a model that answered in prose are said out loud instead of hidden behind the spinner. On the desktop and the web app.
- ⏱️ **World from Wiki stops throwing away slow answers** — the scout now asks the index in parts of about forty cards instead of one long answer, waits longer for a bigger answer (six minutes, plus six more for every 4K tokens the reply may run) before asking again, and holds a first try's thinking to 4K tokens, so a thinking model on a remote provider no longer runs past the cutoff with its answer thrown away. The write is built for a remote provider too: the index's parts, the fill pass's gaps and every place's book go out three at a time, each card reads a 6K clip of its page, and a sentence that ends just past the length cap is kept whole instead of cut mid-word. Forty cards in seven books took nineteen minutes on Kimi K2.6 where the run before took ninety for five. On the desktop and the web app.
- 🔁 **World from Wiki reviews its own work** — the wizard no longer trusts one answer. A Depth pick on the Book step (Quick, Full, Deep) sets how far it digs — Full aims at about sixty cards with each faction's and place's people named inside its own card, the way a hand-built world does it, and only Deep gives every member a card of their own — and a Moment line ("the night after the first invasion") pins every card to that point in the story. At Full and Deep, a reviewer reads the proposed shelf as a roleplay world and sends it back with findings; a fill pass reads the wiki's own categories for what is missing — the Royal Guard's members, a place's residents, the main cast, a top place not yet on the shelf — and asks for exactly those; and every written entry is read against the Moment and its article, with the weak ones rewritten from the findings. Entries chain the way the hand-built worlds do: a place or faction names the cards it should pull and the members or landmarks its article gives it, keys include the titles and accentless spellings a player would type, and at a bigger context each card reads deeper into its article. On a remote provider two batches are written at once. On the desktop and the web app.
- 🏰 **World from Wiki builds a world, not a cast list** — on a big wiki (Fandom, Wikipedia) the scout used to read the first few hundred pages in alphabetical order and propose whoever starts with A or B; it now reads the pages the wiki links to most, plus whatever your premise finds, so the main cast, the places, the factions and the key terms are what it sees. The shelf is shaped like a setting bible: one era card, the places (nested where one lies inside another, up to twelve), the factions, the events, the powers and terms, and only then the people, each written as they are in the premise's time; every card says what it is (place, faction, event, concept, race, item, person). A review pass checks the shelf for that shape and, when it reads as a list of people, asks the model once to revise it. A write batch, a place profile or the climate call that stumbles (a busy provider, a reply that never came) is asked again instead of silently dropping its cards, and each place's own card now lives in the book around it, so a scene in Karakura still knows what Seireitei is. And the Setup step no longer loads a model the moment you pick it: on oMLX or LM Studio the tools check is a model load, so it now runs when you press Next (or Check now); the pick is the wizard's own and never switches chat's model, a model list that will not load no longer replaces your pick, and a model that failed the check is asked again by Next (or Check now) instead of being trusted to have failed, so a verdict filed while the server was still loading the model is not the end of the road. The Book step's Moment line is now called "Where the story stands" and says what it does. On the desktop and the web app.
- 🧭 **World from Wiki gets its own context** — the Book step now has a Context for this wizard pick (Same as chat, or 16K to 256K), and every request the wizard makes is sized to it: an index that would not leave the model room to answer is asked in parts and merged, a reply that still runs out of room is asked again on a smaller part, write batches pack as many cards as the window holds, and the climate and place-profile calls get what the window leaves. The old fixed 3,072-token reply ceiling that the places upgrade outgrew is gone. When something still goes wrong the wizard says what — the model ran out of room even for the smallest part, its server was busy, the reply could not be read — instead of "try a clearer premise". MediaWiki wikis (Fandom, Wikipedia) now really hand the scout their categories, which were being dropped, so their places show up too. On the desktop and the web app.
- 🧮 **Steadier prompts and an honest Context Budget** — the "react to it as yourself" reminder that web search and your tool cards add now sits after the chat instead of at the top of the prompt, so a Continue or an auto-chat turn no longer makes KoboldCpp re-read the whole conversation; the Context Budget's rows and Total are counted with the model's own tokenizer on KoboldCpp (an estimate elsewhere) for both the last send and Refresh, so the number you compare with your context size is the real one; and the Author's Note now fills in the character's name and yours like every other block, in replies, Continue and Impersonate. On the desktop and the web app.
- 🗺️ **World from Wiki now finds the places** — when a wiki keeps its nations and regions in page tags or categories (Tiddly and MediaWiki), the scout now sees those tags and proposes the places they imply: the review shelf groups its cards by place with a per-place weather switch, each place gets its own short description and (where the sources show one) its own climate, and Save creates the world as a root with real places inside it instead of one flat book. A wiki with no tags still yields exactly the single flat world it always did. On the desktop and the web app.
- 🌱 **The story can found a place** — with Scene suggestions on, when the narration settles somewhere your world does not have yet, the app asks "The story just described the Salt Garden — save it as a place inside the Ropewalk?" and writes nothing until you answer. Just add saves it as a child of the current setting with a short description and a few lore entries written from what the story showed, inheriting the weather around it; Add and move also takes the scene there and demotes the old setting to your Lore places; Ignore means that name will not come up again until you re-open the chat. Like Scene Guests it is marked as model-made and you can edit or delete it like any place. On the desktop and the web app.
- 🧭 **The scene can move when the story arrives** — with a new Porch Life switch, Scene suggestions (off until you turn it on, needs Passage of Time), the turn read that already moves time also notices when the narration walks into another place in your world: the app asks "The story reads as arriving at the Tea Rooms — move the scene there?" and only moves it if you say yes. Staying is remembered for that spot until the scene next moves; plans and mentions never trigger an offer. On the desktop and the web app.
- 🌦️ **A world's weather switch covers its places** — turning a top-level world's climate off now means no weather anywhere inside it. Adding or editing a place there says "Weather is off for <world>", a place that already has its own climate keeps it but shows it as paused (in the editor, on its card and in the chat's Places panel), and the world's editor lists which places are paused. Turn the world's weather back on and they pick up where they were. On the desktop and the web app.
- 📍 **Adding a place reads like adding a place** — "Add a place inside" now opens a dialog titled "Add a place to <world>" with a Place name field, a plain Description and an Add place button, instead of the new-world wording. The lorebook is labelled as the place's own and says how many entries it already gets from the world around it, and picking Own climate opens the climate editor right under that choice rather than further up the form. On the desktop and the web app.
- 🗺️ **Places travel together** — exporting a world (or one place inside it) now packs its location tree into the .fpworld file, and importing rebuilds the nested places with fresh ids and keeps where each came from; exporting a single place carries its world and the branch down to it, so nothing orphaned rides along. Stoop WORLD cards share the same envelope, so a card you post carries its places too, and older files without a tree still import exactly as before. On the desktop and the web app.

- 👥 **Cleaner group prompts** — every group turn is now built the same tidy way: your group prompt sets only the writing style, Front Porch adds its own turn rules (or Director Mode's) after it, the speaking character's card and examples sit in one block after the chat, and Author's Notes and Director goals stay near the end where models heed them. Fixes instructions running into the previous message in groups without a scenario, visitors forgetting where the scene is, card post-history instructions being ignored in groups, example lines being mistaken for recent chat, Continue only stopping the model from writing for you rather than the rest of the cast, and Impersonate while directing now writes your next stage direction. On the desktop and the web app.
- 🎬 **Director Mode keeps its rules under your own prompt, and one Group system prompt for every group** — a custom group prompt no longer drops the rules that keep you out of a directed scene, and while you direct the cast is no longer told you are the person they are talking with, so characters stop turning to you and auto-chat stops pausing. Settings → General now has a Group system prompt that every group uses (a group can still set its own in Group Settings), the Director prompt is rewritten, and the With you / Away check gets its line breaks back. On the desktop and the web app.
- 📝 **Saved prompts for both Settings prompts, and built-ins you can't overwrite** — the Fallback system prompt and the Group system prompt each keep their own pick from one shared list of your saved prompts, with a badge saying whether the box holds a built-in, a saved prompt (and whether you've edited it), or unsaved text. Save updates the prompt you loaded, Save as new never overwrites a name you already have, and Reset to built-in (with Undo) replaces the old preset buttons, so the shipped prompts stay out of the list and can't be saved over. On the desktop and the web app.
- ⚡ **More of the graphics card for KoboldCpp** — while a local model is reading or writing, the app now does less drawing of its own: the blur behind a Realism check is drawn once instead of every frame, a streaming reply redraws only the transcript and the status bar instead of the whole chat page, the KoboldCpp console updates a few times a second rather than on every token (and not at all while Home is hidden), and small portraits are decoded small. Replies on a busy card start and stream sooner. On the desktop.
- 🪟 **The Model Manager stays smooth while a model downloads** — on Windows a download made dragging, resizing and scrolling the window crawl. Download progress now redraws only the queue panel and the row that is downloading instead of the whole Model Manager page and Settings, and a collapsed search result no longer builds a row for every file out of sight. On the desktop.
- 🔥 **Afterglow has one switch** — turning on Afterglow in Porch Life now turns on the Lust bar and arousal in every chat, including chats you started before. Before, an old per-chat NSFW Enhancements switch in the chat sidebar quietly overruled it. That old switch, the matching card in Group Settings and the per-character Afterglow switch are gone. Afterglow counts only while 18+ themes are on, and its row stays hidden until they are. A character's Recovery settings show in the editor whenever Afterglow is on. On the desktop and the web app.
- 🎛️ **One-Shot Eval moves up, the chat Needs switch goes** — One-Shot Eval (Auto / On / Off) now sits at the top of the chat sidebar, right above the tool-calling pill it depends on, instead of behind the gear in Character State. The gear and its old per-chat Needs Simulation switch are gone: Needs is set per character in the editor, and changing it there now turns Needs on or off in that character's existing one-on-one chats too, the open one at once; groups keep their switch in Group Settings → Needs. On the desktop and the web app.
