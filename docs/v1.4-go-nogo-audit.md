## P0 — must clear or withhold before a 1.4 cut

### P0-1 — Dual-local GPU turn-taking is advertised; soak and tests are theater

What’s New tells users two local engines take turns on the GPU (including two GGUFs on the one managed Kobold). That path has never been soaked on a real GPU.

- No E2E / inventory row. Flutter tests **force GPU swap off** unless a fake occupancy is injected.
- Tests that “allow” dual-local never call the production occupancy builder. Delete that builder and most dual-local tests stay green.
- Live races already showed up later as unit pins (empty spoken reply after restore-mouth; admin unload timeout treated as success). Those pins are not a soak.
- Default-off does **not** save anyone who taps Different host and picks two locals.

**Agreement:** W2, W7b, and W7c all landed here.  
**Hold-out that would unblock a cut:** keep the worker off in What’s New / hide Different-host two-locals until a maintainer-machine soak exists. Worker-off one-backend is not a 1.3.2 behavior regression on paper.

### P0-2 — Waifu Plan is not a read-only Plan (and the test lies)

Users think Plan plans and Build writes. OpenCode’s native Plan refuses file edits. The chip and the test titled “plan mode selects the native plan agent” sell that.

What happens: Plan only changes the agent **name**. The isolated config then **redefines** `plan` with the same coworker prompt and the same file/bash rules as Build (ask-before-write, not deny). Sit down in Yolo, then tap Plan: OpenCode can still auto-allow writes. The unit test never asserts edits are denied.

**Agreement:** W3 (product) and W7b (contract). Nightly copy still talks about a denied Plan write; that string is not in the app.

**Hold-out:** do not ship Plan as the safety chip until Plan actually denies writes (and a test would go red if it did not) — or rewrite the copy to “Plan still asks to write.”

### P0-3 — A cut from this tip ships the wrong What’s New; default promote erases 1.3.2 history

`docs/main.md` is what `release.yml` pastes into the GitHub release and the in-app Update dialog. On Rawhide it is still the v1.1.1 Linux hotfix. There is **no 1.4 section**. On `main` it is still v1.3.2.

Promotion keeps README / `docs/main.md` from `main`. It does **not** keep `docs/release-notes.md`. Rawhide’s long-form notes still say current stable is **v1.3.1** and have **no 1.3.2 / Make a Wish section**. A default promote **overwrites the 1.3.2 record**.

**Source:** W6 (high confidence). W7c independently: in-repo manuals still sell 1.3.1.

### P0-4 — Thin post-merge CI assumes a merge gate that is not holding

#276 skipping E2E / goldens / live Stoop on Rawhide **push** is fine only if nothing lands without a finished green PR suite. Same-day merges landed **before** goldens/E2E finished; at least one landed **after goldens were already red**. `test-integrity` does fire (it protects editing tests/CI). It does not mean “the suite passed.”

After #276, a squash to Rawhide keeps: empty analyze, always-green full-lint (`|| true`), empty theme/io, Ubuntu unit+widget (goldens excluded), and WebUI vitest. Monday cron is the next automatic full net.

**Disagreement resolved:** W6 filed thin-push as P1; W7c filed it as P0 with merge-vs-check timestamps. Quality-first synthesis takes **P0 process**. This tip’s PR (#275) did later go fully green — do not cut a *later* direct push or a merge-around-red.

### P0-5 — Tip versions are placeholders; a green cut job is not proof the stamp landed

Hostile hypothesis **verified as intended design**, not a new code defect.

- Tip (and v1.3.2) still commit `appVersion = 1.0.0` and pubspec `0.9.8+1`. CI rewrites both from the git tag. v1.3.2 used this path and published real installers.
- The “verify” step only **prints**. If the rewrite misses, the job still goes green and binaries ship as **1.0.0**. The updater would then treat a “1.4” build as older than 1.3.2.

**Cut rule:** do not hand-edit those files; tag `v1.4.0`; **read the CI log for the stamped strings** before calling the release done.

## Five poke scripts (maintainer machine)

1. **Dual-local soak (clears P0-1).** Two locals (Kobold+oMLX **or** two GGUFs on one Kobold). Same process ID across a turn. Feelings, then a visible spoken line, several turns. Cancel mid-eval. Continue. Regen. Timeout/hang must put chat speech back and must not look like success. Same pair stays loaded; different pair unloads/reloads; no restart spam.
2. **Waifu Plan is read-only (clears P0-2).** Sit down → Plan. Ask it to write a file. It must refuse (not merely ask). Sit down in Yolo, tap Plan, ask again — must not still auto-write. Change the chip without sending; leave and reopen — chip must match what you left.
3. **Group Away.** All Away, send a line: you wait, then the skip banner (not instant like 1.3.2). `@` an Away friend — they check in and speak. “Ana, you coming?” does not drag them. Mid-sentence name does not. On the **phone**, after a spoken line + skip, confirm Regen/Continue on the banner do not look like a real reply.
4. **Pockets hide ≠ erase, group already exists.** 1:1: turn one card’s Pockets off, confirm kit is hidden not wiped, turn back on — kit still there. **Then** open an existing group: turn that person off in-chat, leave, reopen — if they come back on, this P1 is real. Hand-off must not land on someone who stayed off.
5. **Cut hygiene (clears P0-3 / P0-5).** Before tag: `docs/main.md` is 1.4 What’s New, not 1.1.1 or 1.3.2. Promote dry-run does not delete the 1.3.2 long-form section. After tag: open the release job log and read the stamped `appVersion` / pubspec — must be `1.4.0`, not `1.0.0`. Do not cut from a Rawhide push that skipped goldens/E2E; wait for a finished green PR suite on that commit.
